# ADR-0006 — CI/CD Pipeline

**Date:** 2026-04-30  
**Status:** Accepted

## Context

The platform needs an automated quality gate and image publication pipeline that runs on every
PR and every merge to main.  Candidates: GitHub Actions, CircleCI, Jenkins/Tekton on-cluster.

## Decisions

### GitHub Actions

GitHub Actions is co-located with the source repository, requires no external account or
infrastructure, and provides free runners for public repositories.  CircleCI and Jenkins both
require external configuration and offer no meaningful advantage for a single-team repo.

### Three workflows

| Workflow | Trigger | Purpose |
|----------|---------|---------|
| `ci.yml` | every push + PR | Lint (ruff), type-check (pyright), unit tests, integration tests |
| `build.yml` | push to `main` only | Build production images, push to GHCR |
| `helm.yml` | every push + PR | `helm lint` + `ct lint` all charts |

Build is decoupled from CI deliberately: PRs should not push images; only merged commits
produce artefacts.  `concurrency: cancel-in-progress` on the CI workflow drops superseded
runs on rapid pushes.

### GHCR over Docker Hub / ECR / GCR

GitHub Container Registry is co-located with the source, authenticates with the built-in
`GITHUB_TOKEN` (no secret rotation), and is free for public repositories.  Images are tagged
only with the immutable commit SHA; promotion must update chart values to that SHA rather
than consuming a mutable `latest` tag.

### testcontainers for integration tests

Unit tests use SQLite in-memory (fast, no Docker required).  In CI, integration tests use a
GitHub Actions Postgres service container exposed through `INTEGRATION_DATABASE_URL`.  Local
integration runs can still fall back to `testcontainers[postgres]` when that URL is absent.
Gate: `INTEGRATION=1` env var — not set locally by default, set explicitly in CI's
integration test step.

The integration boundary is the database: Celery task dispatch is mocked in report-api
integration tests because the worker is an independent process.  Running a full Celery stack
in CI would require Redis and a worker container, adding ~2 min to the job with marginal
coverage gain over existing worker unit tests.

### Pyright for type-checking

Pyright replaces mypy across all services.  Key reasons:
- Native Pydantic v2 support (no plugin required)
- Faster incremental analysis
- Better LSP integration (Pylance shares the same engine)
- `typeCheckingMode = "standard"` balances strictness without mypy strict mode's false-positive
  rate on SQLAlchemy's dynamic column descriptors

`loadgen` uses `typeCheckingMode = "off"` — locust stubs are incomplete.

### Matrix strategy with `fail-fast: false`

Each service is an independent job.  `fail-fast: false` ensures a lint failure in one service
does not cancel the remaining jobs — reviewers see the full picture in a single run.

## Consequences

- Every PR must pass lint + unit tests before merge.
- Integration tests run in CI against a throwaway Postgres container; no persistent test
  database is needed.
- GitHub Actions are pinned to immutable commit SHAs, so upstream tag mutation cannot change
  the workflow without a source change.
- Production image builds publish SBOM/provenance attestations and run Trivy vulnerability
  scanning before the build job is considered green.
- GHCR images can be pulled directly by staging ArgoCD applications by updating `image.tag`
  in `charts/*/ci/staging-values.yaml`.
- `uv.lock` files must be committed per service; the `setup-uv` cache key is the lock file,
  so cache misses only occur on dependency changes.
